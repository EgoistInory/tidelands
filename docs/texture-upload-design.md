# 下一冷场批次：开始游戏前分帧准备本地纹理

沙粒版已交付，当前实验使用两个独立WebGL上下文，未修改生产加载。九张草/沙/石料JPG通过每RAF一次initTexture全部移到首次draw之前；单次CPU5.6–18ms，首draw仍122.7ms。原统一上传页首draw198.4ms，独立上下文和一次样本不支持固定百分比优化。详见texture-upload-review.json。

实施边界：由ground/rock表面显式提供已成功解码的纹理列表，复用已有加载状态；不要在生产通过手动onBeforeCompile检查查找纹理。开始页显示具体准备进度，每帧最多初始化一张贴图，全部准备后开放开始入口。任一素材失败继续原地表，不能让失败promise或离开页面留下永久加载。处理上下文丢失/恢复和中止时应检查当前renderer状态，避免给已失效上下文继续上传。

首先区分纹理上传、shader链接和生成贴图的剩余成本，不能把准备前移说成总成本减少。用失败注入和冷上下文真实GL检查上传调用次数、开始按钮状态、取消/恢复；再验收普通新档与损坏素材回退的实际UI，并取当前源短动态/GPU证据和版本化交付。完整质量的长时GPU/显存与真机仍独立待办；不以这项启动调度代替3A目标。
