## 它怎样做到小而有整体效果

| 源码位置 | 实际设计 | 适合本项目的启发 |
|---|---|---|
| L349起的内联Three.js，L4733渲染调度 | 引擎也在单文件里；离线资源不等于零引擎成本。按档位设像素预算、后期目标和阴影质量 | 看实际运行像素/显存预算，不追求把源码硬塞成单文件 |
| L5283、5442、5814 | Canvas生成贴花、标识、材质图集；几何组合后复用。颜色、法线、粗糙度组合形成大面细节 | 用共享程序材质和少量几何规则，优先改善整个海岸/营地的层次 |
| L5585–5650地面着色器 | 潮湿、积水、反射粗糙度、波纹按统一空间分布融合，随距离淡出细节 | 海水、湿岸、天空和岩面应共用环境逻辑；只换高清素材无法建立统一观感 |
| L4210起天空、L4597–4733后期 | 云层、太阳光晕、HDR缓冲、曝光、光晕/条纹、暗角和色调映射串成整体；开镜、闪光、受伤也进入画面反馈 | 建立整场画面管线；保持可读性，避免用过量滤镜掩盖形体问题 |
| L5928声音生成/缓存与玩家参数 | 由生成器产生PCM并缓存到AudioBuffer，再按事件播放；后坐、恢复、摆动有不同时间参数 | 生成一次复用，声音与实际动作事件结合。不能把“程序生成”误解成每帧重建所有素材 |

源码内游戏部分没有外部模型/纹理加载器调用，未发现内嵌image/audio data URI；有Google Fonts CSS请求（L5–6）。因此“全部没有网络依赖”不准确，字体可回退。单雨港关卡、三中继目标、两类敌人让构图和反馈能够集中打磨；第一人称也减少了第三人称全身动作与绕障镜头负担。这些范围差异解释实现方式，不能替代对我方推进低效的纠正。
